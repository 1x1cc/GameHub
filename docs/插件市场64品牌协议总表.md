### 雷柏（Rapoo, VID 0x24AE）协议要点

⚠️ **最终方案：独立进程（`Tools/RapooCli`）**。进程内直接读会失败——Windows HID 输入报告
只投递给「最先打开该集合句柄」的一方，GameHub 主进程里其它 HID 读取器抢占了雷柏 vendor 集合，
导致「写触发帧成功、读却持续超时」。把读取移出进程后彻底消除竞争，连续轮询 100% 命中。

协议本身（已在真机验证）：与罗技/雷蛇那种「发查询等应答」不同，雷柏是**被动推送**式：

1. 只认 VID `0x24AE`，且必须是 **vendor 集合**（report descriptor 的 usage page = `0xFF00`）；
2. 官方实现只打开集合持续读输入报告（200ms 超时轮询），**不依赖查询命令**；
   另会先写一帧触发帧 `report id 6 + A5 A3 00 00 00 00 00 00`（部分集合上会写失败，但报告照样来）；
3. 解析规则（下标含 report id 占位）：
   - `len >= 19 && buf[0] == 0x07` → 电量 = `buf[8]`
   - `len >= 7 && buf[0] == 0xBB` → 电量 = `buf[6]`
   - 只接受 `1..100`

本机实测（`VID_24AE/PID_1462`）的 vendor 集合分布：

| 集合 | usagePage | usage | in/out | 有无电量 |
|---|---|---|---|---|
| `mi_01&col05` | 0xFF00 | 14 | 33/33 | ✗（触发帧可写） |
| `mi_01&col08` | 0xFF00 | 17 | 32/32 | ✗ |
| **`mi_01&col09`** | **0xFF00** | **2** | **19/19** | **✅ 电量报告（触发帧写失败也照样来）** |
| `mi_01&col0a` | 0xFF00 | 18 | 24/24 | ✗ |
| `mi_02` | 0xFF00 | 1 | 513/513 | ✗（推 513 字节全 0 噪声） |

⚠️ 注意：参考实现偏好 usage ∈ {14, 15}，但本机电量实际在 **usage=2** 的那条集合上，
所以 GameHub 的实现按「报告长度短的优先、全部试一遍」来排，不硬编码 usage。

### 致动手柄（VID 0x413D / PID 0x2204）为什么读不到

- 该设备在系统里枚举为 `XnaComposite`「支持 Windows 的 XBOX 360 手柄」→ **XInput 仿真成有线手柄**，
  `XInputGetBatteryInformation` 只回「有线」，拿不到百分比（GameHub 会如实标注原因）；
- **参考实现里根本没有致动插件**（全文本检索 `致动` / `ZD` / `413D` 命中 0 次），
  所以**买会员也读不到这只手柄**；
- 但它的 `mi_02` 是一条 vendor 集合（usagePage=`0xFF7A`，in/out 均为 65 字节），
  理论上可逆向 → 属未来可探索方向，需用 USBPcap 抓官方驱动的报文。

## 关键结论

1. **插件市场 = 内置 64 个品牌 provider + 付费解锁开关**，不是"下载插件"。每个插件是一个
   `C.P` 实现类，带 `Metadata { Id, BrandName, Is24GPlugin, Requires24GAddon, DeviceSource, SupportedDevices[] }`。
2. **2.4G 插件全部属于"24G 加购"权益**（`Is24GPlugin=true`，`IsAddonRequired=true`）。
   未购买时日志会打印 `[Plugin] Skipped (disabled): <品牌>`（本机实测 64 个全 disabled）。
3. **每个品牌的协议是独立 provider 类**（自定义 VID / 查询帧 / 电量偏移），**没有统一的单一协议**。
   常见查询帧举例（`new byte[]`）：
   - ROG：`[rid, 0x12, 0x01/0x07]`（0x12 子命令族）
   - WLMOUSE：`{0,0,0,2,2,0,131}`（自定义 7 字节帧）
   - Razer：14 字节 `QueryPrefix`（自定义帧）
   - 某品牌：`{5,1,22}`、`{14,165,11,1,1}`、`{19,5,1,0}` 等
4. **字符串"加密"其实是 XOR 混淆**（`b ^ i ^ 0xAA`），静态即可还原——所以协议数值（VID/PID/偏移/查询帧）
   与品牌名、型号名**全部可离线读取，无需购买会员**。购买会员只额外解锁"实机运行 + 日志十六进制基准"。

## ROG（ASUS）完整协议表（已并入 GameHub）

- **VID** `0x0B05`；无线键盘查询 `[0x02, 0x12, 0x01]`（mi_02&col02），鼠标 `[0x03, 0x12, 0x07]`（mi_00）。
- 电量偏移：键盘 `[6]`（夜魔家族取 `[11]`），鼠标 `[5]`；充电位键盘 `[9]`、鼠标 `[10]`。
- 无应答标记 `[1]=0xFF [2]=0xAA`。
- **73 个鼠标 PID**（含精确 HID 路径 mi_00/mi_02）+ **76 个无线键盘 PID** + OMNI 接收器 `0x1ACE`/`0x1AD0`。

本次已把 GameHub `RogBatteryReader` 的型号表**从 60 个 PID 补齐到 149 个**（+43 鼠标 +66 键盘），
并新增 `Mi(n, reportId)` 通道与 `MouseMi0Rid3`/`Keyboard24G` 两条通道，直接覆盖此前认不出的 ROG 键盘/鼠标。
